# Code signing status

BookDB 1.8.0 is unsigned. No signing provider has approved this project.
The original release remains unchanged; signing would change the executable
and require new checksums and a clearly identified new release.

## Route being evaluated

[SignPath Foundation](https://signpath.org/terms) offers free signing for
qualifying open-source projects. Approval is discretionary and includes review
of project reputation. Its certificate identifies SignPath Foundation as the
publisher, rather than providing a personal certificate to the developer.

Before applying, BookDB needs a maintained public source repository, an
OSI-approved licence with compatible dependencies, a verifiable automated build,
documented functionality, and assigned signing roles. Maintainers must use MFA;
release signing requires manual approval. These are preparation requirements,
not claims that BookDB has already met them. No application has been submitted.

Microsoft [Artifact Signing eligibility](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)
currently includes individual developers in the US and Canada and organizations
in supported countries including the EU. Eligibility must be checked for the
actual publisher; an individual in Slovakia should not assume eligibility.
A commercial certificate is another possibility, subject to provider validation
and fees. No subscription or certificate has been purchased.

Self-signed certificates do not establish public publisher trust. Signing also
does not guarantee that Windows reputation warnings disappear immediately.

Source and licensing decisions must precede a signing-service application.
Application code and third-party catalogue content require separate licensing
consideration; no blanket licence is granted to imported list content here.
